# دفتر الحساب (Daftar Al-Hisab)

تطبيق فلاتر لإدارة يوميات العمال، الورشات/المشاريع، والمدفوعات — مصمم لأصحاب الورش والمقاولين لتتبع أجور العمال اليومية والسلف والرصيد المستحق لكل عامل، **وأيضاً للعامل نفسه** ليسجل عمله ويتابع رصيده.

## المزايا

- **اليوميات**: تسجيل يومية عمل لكل عامل (الاسم، الورشة، الأجر، ملاحظات) مع إنشاء تلقائي للورشة إذا لم تكن موجودة.
- **الورشات والمشاريع**: عرض كل ورشة مع إجمالي أيام العمل، التكلفة الإجمالية، آخر نشاط، وحالة المشروع — مع إمكانية التعديل والحذف.
- **العمال**: قائمة بجميع العمال مع الرصيد المستحق لكل واحد منهم — مع إمكانية التعديل والحذف.
- **الملف الشخصي للعامل**: الرصيد المستحق، إجمالي اليوميات، إجمالي السلف، سجل الحركات الكامل، تصدير كشف حساب PDF (بدعم كامل للنص العربي)، ومشاركة سريعة.
- **المدفوعات**: تسجيل دفعات أسبوعية أو سلف نقدية أو تسويات حساب لكل عامل.
- **التقارير**: نظرة عامة على التكلفة حسب كل ورشة والعمال الأكثر استحقاقاً.
- **وضع العامل**: يمكن للتطبيق أن يُستخدم من طرف العامل نفسه (بدل صاحب العمل) لتسجيل يومياته ومتابعة رصيده الخاص — يُفعَّل من الإعدادات ← نوع الحساب.
- **نسخ احتياطي**: تصدير جميع البيانات كملف JSON عبر قائمة المشاركة، واستيرادها لاحقاً لاستعادتها.
- **نسخ احتياطي سحابي على Google Drive**: تسجيل دخول اختياري بحساب Google، مع نسخ احتياطي تلقائي بعد كل تعديل، وإمكانية الاستعادة من أي جهاز — بما في ذلك شاشة تظهر عند أول فتح للتطبيق تسأل عن استعادة نسخة سابقة أو التخطي.
- **تنبيهات يومية حقيقية**: تذكير مجدوَل فعلياً (وليس مجرد مفتاح شكلي) لتسجيل يوميات العمل، بوقت قابل للتخصيص.
- **تحديث تلقائي**: يتحقق التطبيق من وجود إصدار أحدث عبر بيان JSON مستضاف على GitHub Pages، ويوجّه المستخدم لرابط MediaFire للتحميل.
- **شاشة "ما الجديد"**: تظهر تلقائياً مرة واحدة بعد كل تحديث لعرض أبرز التغييرات.
- **دعم متعدد اللغات**: العربية والإنجليزية والتركية، مع دعم كامل للاتجاه من اليمين لليسار (RTL) في الوضع العربي.
- **حول التطبيق وسياسة الخصوصية**: معلومات حقيقية عن التطبيق والمطور (ياسر أبو علاء)، وسياسة خصوصية تصف فعلياً كيفية تعامل التطبيق مع البيانات.
- **الدعم الفني**: قسم مخصص يفتح محادثة واتساب مباشرة.
- تخزين محلي بالكامل (SQLite) — لا حاجة لإنترنت أو خادم، إلا للتحقق من التحديثات أو عند مشاركة الملفات باختيارك.

## البنية التقنية

- **Flutter** (Material 3) + **Provider** لإدارة الحالة.
- **sqflite** لقاعدة بيانات محلية.
- **shared_preferences** لحفظ إعدادات المستخدم.
- **pdf** / **printing** لتصدير كشوف الحساب، مع خط **Amiri** (`assets/fonts/`) لدعم النص العربي في ملفات PDF.
- **flutter_local_notifications** + **timezone** للتنبيهات اليومية الفعلية.
- **file_picker** لاستيراد ملفات النسخ الاحتياطي.
- **http** للتحقق من التحديثات.
- **google_sign_in** + **googleapis** للنسخ الاحتياطي السحابي على Google Drive.
- **share_plus**, **url_launcher** للمشاركة والاتصال المباشر بالعامل وفتح واتساب.

## إعداد ميزة النسخ الاحتياطي السحابي (Google Drive)

الكود جاهز بالكامل، لكن Google Sign-In يحتاج إعداد مرة واحدة من طرفك على Google Cloud Console (خطوة لازم تتم يدوياً لأنها تتطلب حسابك الشخصي على Google، ولا يمكن أتمتتها بتوكن GitHub):

**بصمة SHA-1 الخاصة بتوقيع التطبيق (ثابتة الآن، لا تتغير بين كل بناء):**
```
46:D6:14:95:C2:9E:E9:D9:56:F6:81:57:E0:E5:06:19:53:A8:9E:74
```
**اسم الحزمة (Package name):** `com.abwaalaa.daftaralhisab`

> ملاحظة مهمة: ولّدت مفتاح توقيع (keystore) دائم لهذا الغرض وخزّنته كأسرار (Secrets) في مستودع GitHub (`RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`) — بدون هذا، كانت بصمة SHA-1 تتغير في كل مرة يبني فيها GitHub Actions التطبيق، مما يكسر تسجيل الدخول بـ Google باستمرار. احتفظ بنسخة من كلمة مرور الـ keystore في مكان آمن (مدير كلمات مرور) لأن GitHub لا يسمح باسترجاعها بعد إضافتها كسر.

**خطوات الإعداد على Google Cloud Console:**

1. افتح [console.cloud.google.com](https://console.cloud.google.com) وأنشئ مشروعاً جديداً (أو استخدم مشروعاً موجوداً).
2. من القائمة الجانبية: **APIs & Services ← Library**، ابحث عن **Google Drive API** وفعّله.
3. **APIs & Services ← OAuth consent screen**:
   - اختر **External**.
   - املأ اسم التطبيق (دفتر الحساب)، بريدك الإلكتروني، وشعار التطبيق إن أردت.
   - في قسم **Scopes**، أضف `.../auth/drive.appdata`.
   - في قسم **Test users**، أضف عناوين بريد Google الخاصة بك وبأي مستخدمين تريد تجربة الميزة معهم (طالما التطبيق في وضع Testing، فقط هذه الحسابات تقدر تسجل دخول).
4. **APIs & Services ← Credentials ← Create Credentials ← OAuth client ID**:
   - نوع التطبيق: **Android**.
   - اسم الحزمة: `com.abwaalaa.daftaralhisab`
   - بصمة SHA-1: الصقها من فوق.
   - احفظ.
5. لا حاجة لتحميل أي ملف (مثل `google-services.json`) — حزمة `google_sign_in` المستخدمة هنا تعمل مباشرة عبر خدمات Google Play بمجرد تسجيل SHA-1 واسم الحزمة، دون الحاجة لـ Firebase.
6. إذا أردت تجربة الميزة أثناء التطوير المحلي (`flutter run` بمفتاح debug عشوائي)، كرّر الخطوة 4 وأضف بصمة SHA-1 الخاصة بمفتاح الـ debug على جهازك (`keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android`).

بعد هذه الخطوات، ميزة "النسخ الاحتياطي السحابي (Google Drive)" في الإعدادات ستعمل مباشرة على أي APK مبني عبر GitHub Actions لهذا المستودع.

**ملاحظة حول وضع Testing:** طالما شاشة الموافقة (OAuth consent screen) في وضع "Testing"، فقط الحسابات المضافة كـ Test users تقدر تسجل دخول (حتى 100 مستخدم). للسماح لأي مستخدم بتسجيل الدخول، تحتاج نشر التطبيق (Publish) من نفس الصفحة، وهو ما قد يتطلب من Google مراجعة إضافية لأن `drive.appdata` يُصنَّف كصلاحية حساسة (Sensitive scope) — لكن هذا غير ضروري لاستخدام شخصي أو مع عدد محدود من المستخدمين المعروفين.

## إعداد ميزة التحديث التلقائي

بيان التحديث مستضاف تلقائياً عبر GitHub Pages من مجلد `docs/` في هذا المستودع:
`https://abw3laa.github.io/daftar_al_hisab/update_manifest.json`

عند إصدار نسخة جديدة من التطبيق:
1. ارفع ملف الـ APK الجديد على MediaFire واحصل على رابط المشاركة.
2. حدّث `docs/update_manifest.json` بالقيم الجديدة: `versionCode` (يجب أن يطابق `flutter.versionCode` في `android/app/build.gradle`)، `versionName`، `mediafireUrl`، و`changelog` لكل لغة.
3. أضف نفس التغييرات في `lib/config/changelog.dart` تحت مفتاح الإصدار الجديد ليظهر في شاشة "ما الجديد".
4. ادفع (push) التغييرات؛ سيتحقق التطبيق تلقائياً من التحديث للمستخدمين عند فتح التطبيق.

## البناء محلياً

```bash
flutter pub get
dart run flutter_launcher_icons
flutter build apk --release
```

سيكون ملف الـ APK جاهزاً ضمن `build/app/outputs/flutter-apk/`.

## البناء عبر GitHub Actions

يحتوي المستودع على ورك-فلو جاهز (`.github/workflows/build.yml`) يقوم تلقائياً ببناء الـ APK عند كل push على `main`، ورفع الملف كـ artifact. عند إنشاء tag يبدأ بـ `v` (مثل `v1.1.0`) سيتم إنشاء إصدار (Release) تلقائياً مع إرفاق ملفات الـ APK.
